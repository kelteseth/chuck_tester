Tester is a C++ library you link into your app. Chuck is the Python controller that drives it. Together they let you — or an AI — test Qt/QML interfaces over a simple WebSocket connection.

```mermaid
graph LR
    A["chuck<br/>(Python)"] <-->|"WebSocket / JSON-RPC 2.0<br/>port 1408"| B["tester<br/>(C++ lib)"]
```

## Why?

- **No injection or hooking** — tester is linked as a normal library, not injected at runtime
- **AI-first** — tests can be written by hand, generated by AI, or driven live through MCP
- **JSON-RPC 2.0** — standard protocol, debuggable with any WebSocket tool
- **Pytest native** — tests are regular async Python, run with `pytest`
- **Visual regression** — screenshot baselines with SSIM, perceptual hash, and diff images
- **Self-healing** — when tests break, an AI agent can diagnose and repair them using the chuck-repair skill

### :material-numeric-1-circle: Link tester into your app

Add three lines of C++ after your QML engine loads. Tester embeds a WebSocket server right inside your process.

```cpp

server.start();
```

## At a Glance

```python
from chuck import ChuckClient

async with ChuckClient(port=1408) as app:
    await app.wait("mainWindow", property="visible", value=True)
    await app.click("createBtn")
    await app.keys("nameField", text="My Project")
    props = await app.get("nameField", props="text")
    assert props["text"] == "My Project"
    await app.quit()
```

## What's in the Box

| Component | Language | What it does |
|-----------|----------|--------------|
| **tester** | C++ | Embeds a WebSocket server in the app, walks the QML tree, executes click/type/screenshot/wait commands |
| **chuck** | Python | Connects to tester, provides async API + CLI + MCP server + JSONL recording |
| **skills** | Markdown | Copilot/AI skills for writing tests ([chuck-testing](guide/writing-tests.md)) and repairing them ([chuck-repair](guide/ai-repair.md)) |
